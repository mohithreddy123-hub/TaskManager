TrackNest - Complete Project Architecture & Setup Guide
======================================================
🌟 1. PURPOSE OF THE PROJECT
----------------------------
TrackNest is a full-stack, personal productivity and finance management dashboard. 
The primary goal of this application is to solve the problem of fragmented personal tracking. Instead of using one application to track to-do lists and another to track daily expenses, TrackNest unifies both into a single, cohesive dashboard. 

The application is designed to be:
- Secure: Every user has a strictly isolated data environment protected by JSON Web Tokens (JWT).
- Scalable: Built with a proper relational database (MySQL) and Django ORM, ensuring it handles large amounts of data efficiently.
- Professional: Follows enterprise-level backend standards (throttling, blacklisted tokens, separated validation layers).

🌟 2. EXACTLY WHAT WE HAVE DONE SO FAR
--------------------------------------
We successfully transformed a basic backend into a robust, production-ready system. Here is the deep breakdown of what was built:

1. Unified Data Model (Proper Storage): 
   - Upgraded the default SQLite database to a robust MySQL production database.
   - Built the `DailyEntry` model which smartly handles both "Tasks" and "Expenses".
   - Created a 3-Tier Status System (`pending`, `in_progress`, `completed`).

2. Advanced API & Security (Proper Backend):
   - Authentication: Implemented JWT-based login/register with automatic token refreshing. 
   - Token Blacklisting: When a user logs out, their token is cryptographically blacklisted in the database so it can never be reused.
   - Throttling (Brute-force protection): Limited the `/login` endpoint to 10 requests per minute and `/register` to 5 requests per minute per IP.
   - Dynamic Validation: Created intelligent serializers that know how to validate different types of data (e.g., rejecting an expense if it lacks a money amount, but allowing a task to save without one).
   - Database Aggregations: The dashboard stats (Total Expenses, Completed Tasks, etc.) are calculated securely and rapidly at the database layer using Django's `Sum` and `Count` annotations, rather than slow Python loops.

3. Dynamic Frontend:
   - Built a sleek, glassmorphic UI using React and Vite.
   - Developed dynamic modal forms that change their inputs based on whether the user selects "Task" or "Expense".
   - Implemented an Axios interceptor that quietly refreshes the user's secure token in the background without interrupting their session.
   - Removed React StrictMode to optimize performance and stop duplicate API network requests.


📦 3. EXACT DEPENDENCIES INSTALLED
----------------------------------
To build this, several powerful libraries were used. Below is the exact list of installations and their specific purpose in this project:

### Backend Dependencies (Installed via `pip install`)
Command used:
    pip install django djangorestframework djangorestframework-simplejwt django-cors-headers mysqlclient

1. `Django` (v6.0.2)
   - Purpose: The core Python web framework. It handles the ORM (talking to the database safely), URL routing, and security middlewares (XSS, Clickjacking protection).

2. `djangorestframework` (DRF)
   - Purpose: Upgrades Django to easily serve JSON data. We used it to build APIViews, throttles, and the serializers that validate our JSON payloads.

3. `djangorestframework-simplejwt`
   - Purpose: Implements the JSON Web Token authentication standard. It generates the `access_token` (15-min lifespan) and `refresh_token` (7-day lifespan) used to secure our APIs.

4. `django-cors-headers`
   - Purpose: Cross-Origin Resource Sharing. Because the React frontend runs on port 5173 and the Django backend on 8000, this library securely allows the frontend to request data from the backend without the browser blocking it.

5. `mysqlclient`
   - Purpose: The high-performance C-based database driver. This is the exact connector Django needs to communicate with the MySQL database.


### Frontend Dependencies (Installed via `npm install`)
Command used to create the project:
    npx -y create-vite@latest frontend -- --template react

Commands used to install dependencies inside the `frontend` folder:
    npm install axios react-router-dom react-hot-toast lucide-react

1. `react` & `react-dom`
   - Purpose: The core libraries for building the component-based User Interface.

2. `react-router-dom`
   - Purpose: Enables Client-Side Routing. It allows users to switch between the Dashboard, Login, and Profile pages instantly without the webpage reloading.

3. `axios`
   - Purpose: A promise-based HTTP client. We used it to send GET/POST requests to the Django backend. It allows us to use "Interceptors" to automatically attach the JWT token to every request.

4. `react-hot-toast`
   - Purpose: Used for the beautiful, animated success and error notification popups that appear in the top right corner.

5. `lucide-react`
   - Purpose: A lightweight, clean SVG icon library. Used for the wallet, checks, and trashcan icons on the dashboard.
